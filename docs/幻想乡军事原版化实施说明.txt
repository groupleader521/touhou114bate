幻想乡军事体系原版化：实施说明
==============================

基准：本机《钢铁雄心 IV》1.19.3 原版文件，以及迁移前本 Mod 的实际装备、科技、兵种定义。
实现时间：2026-10-01。

一、已实施的结构变化

1. 删除 268 个幻想乡科技定义（魔力 85、灵力 63、妖力 69、支援 29、王牌 22）。
   普通科技改用原版科技 ID；王牌项目改用国家旗标和原版科技条件。
   删除旧版 38 项特种部队学说科技覆盖，使用当前原版学说系统。
   恢复原版科技页面与可见性，幻想乡国家可直接研究原版步兵、火炮、装甲、航空和支援科技。

2. 删除 90 个自定义兵种定义。开局编制、解锁编制、AI 模板和 Boss 编制改用原版兵种。
   部队和编制保留；例如人偶步兵营现在使用 infantry，轻型人偶装甲营使用 light_armor。
   名称、型号和图标保留，兵种的基础组织度、人力、宽度、训练时间与装备需求量采用原版。
   原王牌兵种自身的特殊地形、医疗、补给等固有能力不会作为独立兵种继续存在。
   因此保留单件装备数值不代表整营战斗表现与旧版完全一致。

3. 删除 61 个自定义装备原型。保留全部 143 个装备型号 ID，并归入原版装备原型。
   例如 touhou_magic_infantry_equipment_1 归入 infantry_equipment；
   touhou_magic_light_tank_equipment_1 归入 light_tank_chassis；
   touhou_wakan_fighter_equipment_1 归入 small_plane_airframe。
   原版兵种可以使用这些型号，也可以使用兼容的原版装备。
   妖精的 evil_equipment_0 原来同时供步兵、装甲、炮兵使用：保留原 ID 供步兵使用，
   另外复制 evil_armor_equipment_0、evil_artillery_equipment_0，保留其原始数值，分别供原版装甲和炮兵使用。
   实际型号总数为 145。

4. 修正特殊角色映射：
   神风人偶 → suicide_craft；人偶战略导弹 → cas（保留原装备任务列表与一次性属性）。
   天谴道士 → strat_bomber；月都式参谋连 → engineer。
   移动魔法巨炮 → artillery_brigade（原定义是线列炮兵）。
   魔界精锐 → heavy_armor。当前原版超重型防空兵种属于支援连，不能放在原 Boss 的线列营位置；
   因此保留线列装甲角色，改用原版重型装甲营和相应装备需求。
   星莲船 → carrier；潜艇兵种 → submarine。

二、数值保留和科技加成

装备并未按统一百分比削弱。143 个原型号从原装备原型继承得到的明确数值都写入新型号，
包括攻击、防御、突破、装甲、穿甲、速度、可靠性、造价、资源和原本明确声明的燃油等。
逐字段核对了 2,108 项明确数值，没有变化。

例：1936 繁彩魔力发射器仍为软攻 6.6、硬攻 2、防御 20、突破 2.7、穿甲 5、
造价 0.55、可靠性 0.7、钢 3。没有改成原版数值，也没有乘以 90%。

科技的原兵种加成迁移到原版兵种。游戏原版科技已有的相同效果先扣除，再通过国家范围的
add_unit_bonus 加上差额，避免原版和幻想乡效果叠加计算。
共生成 69 组兵种差额和 11 个国家修正。
例：原魔力 support_weapons 的步兵防御/突破 +5%、骑兵 +2%、特种步兵 +3% 继续生效；
原版 1.19 该节点本身没有这些旧加成，所以补回原来数值。
研究完成、开局和切换制造体系时同步；每日检查作为补充。

魔力、灵力、妖力旗标与原有国家精神继续作为制造传统和科技加成条件。
科研奖励类别继续接入原版研究节点，包括歌利亚对应的重型/超重型坦克研究。
研究节点的年代、基础研究成本和分支采用原版；保留的是幻想乡装备性能和原科技效果。

三、设计器与生产

启用 NSB 时，旧坦克科技引用转为原版底盘科技；启用 BBA 时，旧飞机科技引用转为原版机体科技。
未启用相应 DLC 时采用原版固定型号科技。
原幻想乡成品型号保留固定数值，设置 module_slots = none，避免继承原版模块再额外增加成品属性。
它们属于原版原型，原版可设计底盘/机体仍同时可用；星莲船保留自己的原模块、槽位和空船体。
星莲船的三个型号属于待装配的模块化船体，不自动创建缺少必需模块的成品船设计。
飞机的舰载资格由原版机体原型决定，删除型号中与原型冲突的 carrier_capable 覆盖。
原版陆基机体下的幻想乡型号不再继承旧自定义原型的舰载资格；这不改动其攻击、造价等数值。

原版装备和可设计底盘保持自己的名称、说明、图标和定义，不再添加幻想乡装备显示覆盖。
幻想乡底盘/武器特色通过保留型号自身的原名称、说明、图片体现，共用原版装备原型。
科技节点补充国家专属名称、说明与图标，复用原魔力、灵力、妖力及支援科技资源。
例如 ALI 的 support_weapons 显示“钢化术”，infantry_weapons1 显示“繁彩魔力发射器”。
所有 145 个保留/派生装备型号都有直接图标映射，避免失去旧自定义原型后显示空白图标。
NSB/BBA 把多个旧角色合并到一个底盘/机体节点时，采用主坦克/主战斗机的名称和图片；
各角色型号的原名称与图片继续保留在装备显示中。科技显示也按国家开局制造传统分类。
科技 ID 与原版装备原型 ID 重合时（例如 super_heavy_tank_chassis），保留原版显示，
避免科技别名连带修改原版装备；对应幻想乡型号自己的原名原图仍保留。

普通幻想乡型号需对应原版科技和制造传统才能生产；王牌需对应项目旗标，歌利亚各代还需相应
原版坦克科技。项目决议继续保留，不再依赖隐藏的幻想乡科技 ID。
原版科技的 enable_equipments / enable_equipment_modules 清单已恢复原版，不含幻想乡型号或模块。
国家历史初始化、研究完成、制造体系切换、项目完成及每日补查调用国家脚本：
符合原有条件时登记 142 个成品型号；另外三个星莲船船体通过项目登记旗标开放设计器。
所有型号的生产条件均要求该国自己的登记旗标，国家脚本只处理幻想乡原始国家标签。
142 个成品型号 active = no，使用引擎支持的国家 create_equipment_variant / allow_without_tech 登记。
三个模块化星莲船船体 active = yes 供引擎建立基础底盘，但仍要求该国项目和登记旗标才可用。
星莲船六类模块槽位与原版槽位类别不重合，保留原模块库，未向原版科技追加模块解锁。
登记用旗标防止重复；切换体系后旧型号的生产条件关闭，新体系型号按已研究科技登记。
装备文件改为 zz_touhou_*.txt，在原版 x_* 原型复制规则之后载入，避免被自动复制并改变数值。
军工组织使用原版分类；旧文件把原版轻型坦克军工组扩大到重型、超重型的覆盖已移除。

四、原型默认值的明确差异

原文件未声明的字段不能声称“数值完全一样”。本次校验另外记录了原版原型提供的默认值：
18 个牵引火炮型号继承 maximum_speed = 4；21 个坦克/飞机型号继承原版 lend_lease_cost（8、10、14、20）；
潜艇和 3 个星莲船型号采用当前原版的 naval_dominance_factor（9 或 300）与 naval_weather_penalty_factor = 1。
这些明细在《幻想乡军事原版化校验.json》的 warnings 中逐型号列出。
迁移没有让未声明资源、燃油或装备自身人员的旧型号额外继承资源需求、燃油或乘员开销，
也没有额外加入原文件不存在的突破、对舰攻击或对舰命中属性。

tools/military_migration_baseline.json：迁移前原脚本文本，用于追溯。
docs/幻想乡装备实际数值对照.json：迁移前装备实际数值与原版对照，保留为基准。
docs/幻想乡军事原版化迁移清单.json：逐型号、兵种、原型、科技和加成迁移表。

tools/military_presentation.cjs：把原名称、说明、图片映射到原版研究/装备显示 ID。
interface/zz_touhou_military_presentation.gfx：自动生成的原图片引用。
tools/check_country_equipment_conditions.cjs：检查国家装备登记条件的代表性场景。
docs/国家装备解锁条件校验.json：条件检查结果与实测边界。
