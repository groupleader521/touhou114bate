Lua 主导内容构建原型：实施与验证
================================
2026-10-02

本阶段已经实现可运行的外部 Lua 构建原型，不写入 Steam 安装目录。
它把 Lua 定义编译为游戏原生 Mod 文件；与游戏进程内的 Lua 加载器是两种不同能力。
原型目录为 tools/lua_loader，使用说明见其中 README.txt。
上阶段二进制研究仍见 可行性与架构分析.txt 与 原版文件与二进制审计.json。

本次已实现
----------
1. Fengari 0.1.5 执行真正的 Lua 内容包，循环可生成中文条目。
2. 包依赖排序、缺失和循环检查、字段与文件冲突检查。
3. 捕获底层本地化原文后追加，生成独立 replace 文件，保留原文转义并采用 UTF-8 BOM。
4. 独立 Sprite 和 DDS 复制；新 GUI 挂到原版装甲科技页指定 parent token。
5. 按块路径修改单个字段，保留原版其他源码，支持 set/remove/append_unique。
6. 源文件、Lua 包、产物哈希记录；输出范围限制、手工修改保护、确定性重复构建。
7. 默认显示模式与可选科技合并模式分开，不将演示写回当前 Mod 的运行时目录。

为什么默认模式不需要 NSB_armor.txt
-------------------------------
基础中型坦克现有描述使用本地化键 basic_medium_tank_chassis_desc。
显示模式只为这个键生成最终文本，并添加独立 GUI / Sprite 文件。
它不改变科技的装备解锁、enable 模块、研究耗时或升级关系。
附加面板通过 original_tag 限定 16 个幻想乡国家，公共描述键的追加则全局生效。
没有重新替换 GFX_basic_medium_tank_chassis_medium，因此不会把公共基础底盘图案改成幻想乡人物。
这是静态生成结构上的隔离结论，真实游戏显示仍待检查。

科技合并演示验证了什么
--------------------
basic.lua 与 advanced.lua 分别给基础中型、改进中型两个节点新增 desc 字段。
构建器从本机原版或更高优先级输入读取有效文件，组合两个补丁，输出一份完整替代文件。
测试移除这两条明确声明的新增字段后，逐节点比较整个原版和生成文件的解析结果。
其他字段、重复条件、enable_equipments 和所有节点必须完全一致，否则检查失败。
测试还核对原版文件哈希、所有构建读取数据哈希和 Lua 输入哈希。

此演示仍生成同虚拟路径 NSB_armor.txt，属于数据库文件覆盖；区别在于由当前输入自动合并。
它解决了手工复制旧文件容易丢失新原版内容的一类问题，不保证兼容一切未知 Mod。
默认显示模式无此替代文件。本项目之前撤掉的原版科技覆盖没有被重新添加到 common/。

验证结果
--------
第一阶段的 22 项检查全部通过；随后输入层扩展至 36 项，详见 输入层与播放集验证.txt。
默认模式 6 个产物文件，合并演示 7 个，均另外带 build-report.json。
重复构建写入未变化产物的次数为 0。
本次独立验证命令与构建清单保存在 原型验证结果.json，后续运行 npm run verify 可更新。
检查覆盖真正 Lua 运行、无限循环停止、非法内容表、依赖图、冲突、重复节点、原文保留、
标识列表追加、Unicode/转义、二进制资源保留、路径别名、输出保护、过期文件清理、原版字段保留。

本阶段没有把示例注册到启动器，也没有启动游戏或注入进程。
界面附加层属于按原版 Scripted GUI 文档生成的候选产物，尚未确认可见位置与引擎加载结果。
Fengari Lua 5.3 是构建环境，不是原版引擎嵌入 Lua 5.1 的替换。
播放集候选解析与目录/ZIP 输入已在随后阶段实现，仍需引擎对照。
没有实现完整领域 API、存档迁移、联机保证与性能基准。

继续扩展的可审查顺序
------------------
先冷启动检查默认显示示例的挂载、分辨率、中文与国家可见性。
输入层候选解析现已实现，接下来对照真实加载顺序、做版本兼容和来源诊断。
最后按装备、科技、国策等领域增加 Lua API 与引擎检查；需要修改数据库字段时显式展示覆盖清单。
运行时原生桥接另设实验范围，需要证明初始化时机和可调用对象接口。
现阶段能确认“Lua 作者体验与组合补丁已经可用”，不能确认“完美取代并全面超过原生加载方式”。
