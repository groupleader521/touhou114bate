幻想乡军事体系改造：统计与实施方案
==================================

用户确认方案：保留幻想乡装备型号 ID，统一归入原版装备原型，供原版兵种通用。
本文件保留前期统计与方案。现已实施迁移，实际规则与校验结果见《幻想乡军事原版化实施说明.txt》。

二、目标结构
原版研究节点 → 解锁幻想乡装备型号 → 型号归入原版装备原型 → 原版兵种消耗该类装备。
例：infantry_weapons1 → touhou_magic_infantry_equipment_1（繁彩魔力发射器）→ infantry_equipment → infantry（步兵）。
旧型号 ID 和名字保留，研究路线、类别与部队需求统一到原版；装备数值依据当前文件的逐项审计处理，暂不预设削弱比例。
同一原版原型下的型号在装备类别上通用，最终配发仍受师模板的装备允许列表等限制。
幻想乡的 61 项独立原型全部退役；143 个现有型号逐项转换。
90 个自定义 sub_units 全部替换为原版兵种；保留历史师、空军联队、舰艇的剧情名称，转换其实际类型和编制。

三、装备定义的改法
步兵、火炮、支援装备：将 archetype 指向原版原型，依据当前装备数值与对应原版型号的实际差异逐项处理。
保留型号 ID、名称、本地化、图片与合理的升级顺序。
不要只写 parent = infantry_equipment_1 就认为会继承 1936 步枪全部数值；parent 是装备升级关系，仍需按原版型号重建实际属性。
示例方向（不是已部署文件）：
touhou_magic_infantry_equipment_1 = {
    archetype = infantry_equipment
    parent = touhou_magic_infantry_equipment_0
    year = 1936
    defense = 20
    breakthrough = 2.7
    soft_attack = 6.6
    hard_attack = 2
    ap_attack = 5
    build_cost_ic = 0.55
    reliability = 0.7
    resources = { steel = 3 }
    # 上述是当前繁彩魔力发射器的实际值，仅用于说明转换需要核对的字段。
    # 是否保留各项差异需审阅数值报告后确定；这不是最终平衡方案。
}

三-A、实际数值审计更正（2026-10-01）
之前提出的“主要战斗属性统一原版90%”没有逐项数值依据，现撤回。
以当前 Mod 与本机 HOI4 1.19.3 文件为准，详见《幻想乡装备实际数值对照.txt》及其 JSON 原始数值与来源记录。
覆盖：120 个普通型号、23 个王牌型号、61 个原型；另列 69 个普通兵种和 246 项常规科技的直接修正。
实际结论：魔力、灵力、妖力的各项属性有高有低；妖力四代步枪的主要战斗属性、可靠性、成本、钢材与原版对应型号相同。
不能从名称、科技树说明或少量样例推断整个体系都弱于原版；不再预设统一比例，也不预设统一改成原版成本。
坦克、飞机当前是固定成品装备，文件对照基线为原版固定成品；未完成同模块 NSB/BBA 设计验证，故不能据此宣称其相对设计器成品更强或更弱。
“parent”不用于本次属性继承，型号显式值覆盖其原型链；未完整声明的值不猜为0。
六个喷气型号在 Mod 中年份为1946，而原版对应型号为1950，已在审计中保留年份差异。
原版1.19支援武器Ⅰ解锁新的火力支援单位，而 Mod 仍保留旧式单位防御/突破加成；迁移时需要一起处理。
基础装备、单位修正、科研加成、国家/MIO 效果与最终设计性能分层记录；当前审计尚未模拟最终战斗结果。
游戏数值尚未修改。

四、研究解锁与生产归属
常规研究使用原版科技 ID；在原版科技的 enable_equipments 中补充相应幻想乡型号。
不再保留 touhou_magic/touhou_wakan/touhou_demonforce 独立研究树及其技术效果。
科技进度共享原版路线；通过型号生产条件区分魔力、灵力、妖力国家，避免所有国家都生产全部幻想型号。
生产条件可使用原版已有的 can_be_produced 机制；具体显示、AI 选择与许可生产行为需在样例中验证。
研究风格标记可作为装备文化分类保留；原科技切换决议改为装备风格/设计选择，具体转换避免重置科研。
统一幻想乡后，需要允许原有多体系库存混用，并明确联合国家能够继续生产哪些文化型号。

五、坦克与飞机设计器
不开 NSB/BBA：型号使用原版固定装备类别，具体性能依据当前装备与原版固定型号的实际差异逐项迁移。
开 NSB：旧坦克型号转为对应原版底盘或角色装备型号，补齐模块槽、升级项、角色与预设设计。
开 BBA：旧飞机型号转为对应原版机体或角色装备型号，补齐发动机/武器模块、任务与预设设计。
44 个常规坦克型号、38 个常规飞机型号需要设计器转换。
旧型号 ID 尽量原样用于对应底盘/机体或角色型号；生成的角色派生 ID 与历史设计引用必须在样例验证后固定。
不能只改 archetype、保留旧成品全部攻击/装甲数据，再叠加模块数值；否则会重复计算并失去原版平衡。
原版 x_tank_chassis.txt / x_plane_airframes.txt 使用 duplicate_archetypes 构造坦歼、火炮、防空、CAS 等角色；转换必须沿用相应原版角色原型和生成规则。

七、必须单独处理的王牌
1. evil_equipment_0：一个型号目前供步兵、装甲、炮兵三种自定义兵种使用。原版兵种需求不同，单个型号不能同时归入三个 archetype。保留旧 ID 作为其中一类，另新增同主题的装甲/火炮型号。
2. 鬼王：原兵种混合步兵与装甲分类，需选原版装甲或步兵编制；旧独立兵种能力不会自动保留。
3. 神风人偶与战略人偶：要按实际任务选飞机原型，不能仅凭名称当成导弹；特殊自爆任务与兼容性需独立处理。
4. 歌利亚：改为原版重型/超重型装甲角色设计，专属兵种与科技退役，型号名可保留。
5. 深海少女、星莲船：也在“全部自定义装备/兵种”范围内，需要原版潜艇、航母/重型舰体及模块转换。
6. 月都参谋连：实际主要效果为地形加成，近似工兵方向；未来医疗设备近似医院，移动补给站近似后勤。
7. 超·极限花火：其极高装备攻击与独立特殊部队要改为原版火炮/支援设计；是否保留特殊强度由国策或决议另行表达。
8. 王牌解锁改为决议/国策条件、装备生产资格与设计发放，删除隐藏王牌科技；不以遗留隐藏科技替代。

八、实施顺序与验证
阶段 1：只做一套完整样例：爱丽丝步枪、轻坦、战斗机，以及原版步兵/轻装甲编制。
验证：原版科技是否解锁型号；原版步兵能否补充幻想与外界枪械；库存和生产是否正确；NSB/BBA 下模块、角色、设计、升级是否正常。
阶段 2：按样例转换其余 120 个常规模型、69 个普通兵种及相关历史配置。
阶段 3：处理 23 个王牌型号、20 个王牌兵种、额外 Boss 和舰船设计。
阶段 4：恢复原版科技/学说页，删除自定义科技及 61 项独立原型、90 项兵种的旧定义。
阶段 5：更新 AI、MIO、国策研究加成、事件装备奖励/消耗、开局生产、库存、师模板与各解锁模板；清理引用。
验收范围：三种文化开局、NSB/BBA/MTG 支持组合、统一幻想乡、王牌获得与剧情装备转移。首版以新开局为目标；旧存档迁移另行评估。
