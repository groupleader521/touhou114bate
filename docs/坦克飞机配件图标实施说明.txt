三、游戏接入
原图：gfx/interface/equipmentdesigner/touhou_modules/source/*.png
游戏纹理：gfx/interface/equipmentdesigner/touhou_modules/icons/*.dds
DDS 为带透明通道的 56×42 像素纹理，大小与原版坦克、飞机模块图一致。
裁去空白透明边缘后等比例缩小并保留透明边距；不改绘画内容。
interface/zz_touhou_module_icons.gfx 为每个幻想乡配件定义 GFX_EMI_<配件ID>。
两个 touhou_*_modules.txt 的 gfx 指向配件自己的 ID。
完整装备预设继续使用原型号图片；配件图案只用于设计器中的模块显示。

四、维护方式
tools/module_icon_catalog.cjs 定义各图案主题和配件归类规则。
tools/prepare_module_icons.py 负责透明检查、缩放、DDS 无损格式转换及预览汇总。
tools/module_icon_art.cjs 将图案接入军事迁移生成器。
原始 PNG 和游戏 DDS 均保存在本 Mod 内，可由原图重新导出纹理。
修改生成规则后使用 tools/migrate_military_system.cjs 重新生成，生成文件仍受校验和保护。
配件图标映射清单.json 记录全部配件到图案的对应关系以及素材 SHA256。
预览图保存在 module_icon_art/tank_icons_preview.png 和 module_icon_art/air_icons_preview.png。

五、校验范围
检查全部配件的 gfx、唯一 Sprite、纹理路径、DDS 尺寸、透明像素和素材校验和。
检查专属 Sprite 不与原版模块 Sprite 重名。
继续使用原有军事校验，核对配件参数、预设装配结果与原版装备保护。
游戏启动检查只证明素材可以加载；设计器中的实际摆放仍以游戏界面为准。

七、重新导出与校验命令
在 Mod 根目录执行，顺序如下：
1. 使用已安装 Pillow 的 Python 导出纹理及预览：
   python tools/prepare_module_icons.py
   本机已验证的 Python 路径为：
   C:\Users\Administrator\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe
   在 PowerShell 中可使用 & 加上述带引号的路径，再传入 tools/prepare_module_icons.py。
   预览汇总使用 Windows 字体 C:/Windows/Fonts/msyh.ttc。
2. 重生成配件显示映射和迁移清单：
   node tools/migrate_military_system.cjs
3. 检查 Sprite、DDS、素材校验和与军事体系：
   node tools/validate_military_migration.cjs
4. 检查修改中的空白错误：
   git -c core.safecrlf=false diff --check
迁移和校验工具默认读取本机 F:/SteamLibrary/steamapps/common/Hearts of Iron IV。
游戏位于其他目录时，可把实际游戏根目录作为两个 Node 命令的第一个参数传入。
这套命令只导出现有 PNG 并更新映射，不会调用图像模型重新生成原图。
--partial 只供生成期间检查已完成素材；最终导出应使用完整模式，要求全部 55 张原图存在。

八、替换或新增图案
替换图案：更新 source 下对应 PNG，保留透明背景，再依次执行上一节的导出、重生成和校验。
新增图案：在 module_icon_catalog.cjs 的 assets 中增加主题，并在 assetFor 中明确配件归属。
同时更新 generation_plan.json 中的生成记录，将新 PNG 保存到 source 后再导出。
保持 GFX_EMI_<幻想乡配件ID> 的命名规则，图案共享通过纹理路径实现。
完整图案目录见《配件图标目录.txt》，逐配件映射以《配件图标映射清单.json》为准。
图案中文主题用于素材目录说明，游戏配件显示名称仍取自各模块的本地化键。
不要直接手改已受校验和保护的生成文件；应在对应生成工具中修改规则。
若出现 Generated file was edited，应先核对并保留手动改动，再把改动合入生成规则。
